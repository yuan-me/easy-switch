## 已知实施差异

React 保持列表组件与行 key，用定时扫描更新数据，因此旧 WPF 的 ObservableCollection Reset/文件 watcher 实现没有原样照搬；需要验证新界面的选择、搜索、阅读位置在刷新和页面往返后保持。更新安装目前要求完整退出 Codex，比仅检查瞬时写入更保守。旧实验性页面恢复开关在设置中保持关闭，阅读位置使用 Easy Switch 自身记录。

## 1.0.4 分页历史文件身份修复

- 根因：将分页数据库的 `thread_id` 当作逻辑会话 ID，按 `threads.rollout_path` 选择当前文件；回退后旧文件与当前文件不同，旧文件的合法偏移被拿去校验当前文件，触发边界错误，部分新文件索引还会漏更新。
- 根据 [Codex 固定版本源码](https://github.com/openai/codex/blob/c248f6d48b97eb4a2aa56147a0b11b7d763278b9/codex-rs/thread-store/src/local/thread_history/turn_lookup.rs)，分页索引实际按物理 rollout ID 查询。改为直接按文件名中的 rollout ID 建立偏移映射，删除多余的逻辑会话映射及数据库扫描。
- 修正合成数据后，旧实现的 `growth_rebases_revisions_children_and_sqlite_then_restores_exact_bytes` 稳定复现“分页历史偏移未对齐事件边界”；修复后通过。验证三份历史文件、两份镜像分页数据库、后代引用、正文与序号保留、零/空偏移、完整恢复及部分提交回滚。
- 增加仅存在回退后文件索引时的 API → 官方 → API 回归，验证每轮索引指向实际文件。真实无效偏移与未知结构继续阻止提交，不清空数据库、不跳过校验；异常包含表、列、文件 ID 与偏移，不包含正文。
- 本地 99 项 Rust 测试及 3 组 Playwright 通过。测试均使用合成数据，没有取得报告问题电脑的数据；本轮未重新执行 VM 安装或真实账号切换。

## 1.0.3 重复线程索引修复

- 使用合成会话和多份 SQLite 数据库复现：旧实现对指向同一文件的重复线程 ID 无条件报警；目录大小写与扩展路径别名还能让同一数据库被扫描两次。原实现的四项新增正向回归失败，修复后通过。
- 数据库路径先去重；跨数据库且指向同一文件、归档状态相同的线程合并显示，选择较新索引的展示信息并保留全部数据库来源。相关数据库一起进入既有加密事务，更新供应商、项目、归档、删除及分页偏移；父子关系合并去重。
- 保留对同一数据库内重复 ID、不同会话文件、归档状态冲突的拦截，并提示数据库名称和冲突原因。写入前再次核对索引定位与归档状态，索引在扫描后变动时不提交。
- 新增 9 项回归，覆盖三份索引往返切换、批量操作与完整恢复、部分提交回滚、路径别名、真实冲突、父子关系、外部变更、各数据库的项目引用，以及重复索引下分页偏移仅重建一次。98 项 Rust 测试和 3 组界面测试通过。
- 原生烟测加入两份数据库指向同一合成会话的场景，v1.0.3 实际原生窗口显示一条会话、扫描无警告，预览、导出等 9 项检查通过。本地安装包签名、版本绑定、篡改拒绝与六尺寸图标校验通过。
