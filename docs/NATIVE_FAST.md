# 原生 Fast

## 使用

1. 编辑 Responses API 供应商，在「在 Codex 中显示的模型」中选择模型。Fast 使用同一份列表，无需再选一次。
2. 在该供应商的「高级设置」中开启「解锁原生Fast」，点击「保存配置」。纯 API 和聚合组可分别设置，新建供应商默认关闭。
3. 修改当前供应商的开关并保存后，会提示「重启 Codex」或「稍后」；其他供应商在下次切换时生效。重启会中断正在生成的任务，并按现有流程备份配置、应用供应商。
4. 重启后，在 Codex 模型菜单中点击闪电，变蓝表示已选中 Fast。Easy Switch 的开关只解锁选项，不会自动选中 Fast。实际可用性与费用以供应商为准。

聚合组需要至少一个已启用成员，且所有成员都使用 Responses 协议。Runtime 会检查模型选择和成员协议，不会把 priority 请求转发到 Chat Completions。当前只支持 Responses；Chat Completions 不声明 Fast。

关闭当前供应商的开关并保存后，也会提示重启，重启后才会停用。选择「稍后」可继续工作，准备好后在「供应商」页面点「重新应用」。取消编辑不保存开关，保存失败不会触发重启。退出 Codex 会丢弃内存补丁。若仅退出 Easy Switch，已加载的补丁仍在当前 Codex 文档中，但之后的页面刷新不保证继续解锁；需要时重新通过 Easy Switch 启动。

## 实现与恢复

- 供应商的 `nativeFastUnlock` 独立控制解锁，Fast 范围来自显示模型列表；旧 `fastModels` 字段保留兼容读取，不再控制模型范围。旧供应商缺少独立开关时，继承旧的全局开关；明确保存的开关优先，新建供应商默认关闭。全局开关只用于读取旧配置，不再作为启动依据或显示在设置页。
- 模型目录中写入 `service_tiers` 的 `priority` 和 `additional_speed_tiers` 的 `fast`；不会把这项能力推断为已经完成真实供应商请求。
- 仅对生效配置为本地自定义 API 凭据的启动启用注入；官方登录、混入登录和未知配置不进行认证解锁。
- 启动时分配临时回环调试端口，限定 `127.0.0.1`。只连接单个 `app://-` 页面，校验 WebSocket 地址、模块来源、体积和四个认证门控的完整匹配。
- 模块源代码通过 Codex++ 的本地模块改写器生成，在新文档加载前使用 import map 预载。不会修改 Codex 安装文件，也不会放宽客户端 CSP。
- 不兼容时不部分应用。加载失败会移除启动脚本并尝试恢复原始页面；无法确认时向用户报告失败，不显示成功。
- 调试端口在 Codex 本次进程运行期间存在，本机其他程序可能访问它。关闭开关并重启 Codex 可取消调试启动。不要把该端口暴露到局域网。

## 来源与分发

原生改写器基于 [CodexPlusPlus 00a1355](https://github.com/BigPizzaV3/CodexPlusPlus/blob/00a1355850cec86d606cf09331cfbc5c66d6512d/assets/inject/native-fast-unlock.js)，适配后的源码保存在 `crates/core/assets/native-fast-unlock.js`。不在运行时下载或执行远程脚本。

Easy Switch 1.4.0 采用 AGPL-3.0，发行标签提供对应源码。模块来源、许可证和修改说明见 [第三方说明](../third-party/README.md)。

## 验证边界

2026-11-06 在 Windows 11 虚拟机的 Codex 26.1103.3517.0 中复现并修复了版本兼容问题：新版使用数字命名的 Rspack 异步块，四处 Fast 判断已分散，界面判断还有多个同模块副本。现在从 CDP 获取已加载的本地模块，检查完整调用结构后一起改写；首次启动会有限等待相关模块加载，避免把空模块列表直接判成不兼容。

修复后，通过实际 Desktop 启动流程验证了 Fast 菜单、选中后的蓝色闪电、`service_tier = "priority"`，以及刷新后的选中状态。独立测试目录初始化沙箱时会暂时遮挡 Codex 输入框；刷新后的菜单在 ChatGPT Work 入口继续核对。测试只用合成密钥和本机模拟地址，未发送模型请求，未验证供应商的加速或计费。JS 回归与 5 项 Rust 原生 Fast 测试通过，包括旧版、Rspack 跨块和模块副本、异步加载、失败回退、本机身份和 Copilot 限制。没有恢复语言补丁。

已验证改写器的本机身份范围、默认关闭、四条认证路径、未知结构拒绝、模块导入改写、预载回退；Rust 模拟 CDP 验证成功、版本不兼容与加载失败后的脚本移除。模型目录在独立临时 CODEX_HOME 中通过本机 Codex app-server 的 `model/list` 检查，确认返回 `priority` 元数据。

2026-11-03 在 Windows 11 虚拟机的 Codex 26.1013.4894.0 中验证：通过实际 Desktop 启动流程加载内存补丁，模型菜单出现闪电，点击后变蓝，配置保存 `service_tier = "priority"`。新建对话和续聊发往虚拟机本地模拟接口的主请求均带 `service_tier: "priority"`；生成标题的辅助请求没有该字段。测试只使用合成密钥和独立数据目录，不修改安装文件。

另外修正了未声明模型支持时仍提示「已解锁」的问题，新增回归测试在虚拟机通过。未验证当前主机上的客户端版本，也未调用真实供应商、验证加速效果或计费。早期验证未定位原先缺少闪电的原因；2026-11-06 的复现与修复记录见上文。实际可用性、响应速度和费用由供应商决定。
