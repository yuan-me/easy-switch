测试日期：2026-10-30。Easy Switch 0.1.3 支持下列官方扩展版本。其他版本仍会在切换前停止，不修改配置或聊天。

| --- | --- | --- | --- |
| 26.1002.51308 | 0.162.0-alpha.2 | 隔离测试通过 | 隔离测试通过 |
| 26.1007.21434 | 0.162.0-alpha.17.2 | 隔离测试通过 | 隔离测试通过 |

## 隔离测试

从官方 VS Code Marketplace 下载三个待测版本各自的 Linux x64 和 ARM64 安装包，提取内置程序。在没有网卡、主机共享目录或磁盘的 QEMU Linux 中运行，用合成聊天完成官方、API A、API B、官方的切换。没有使用真实账号或密钥，没有发送模型生成请求。

每个版本、每种架构都验证了：

- 官方 app-server 创建的 SQLite 表和历史回填状态能被迁移工具识别。
- 每次切换后，故意将数据库中的模型和服务商改成错误值，再通过官方 `thread/list(searchTerm)` 重建索引，确认恢复成目标值。
- 使用 `thread/resume` 打开原聊天，确认线程 ID、当前模型和服务商正确。
- 原始历史正文的字节保持不变；app-server 在关闭输入后正常退出。

这三个版本的扩展后端启动及退出代码也已检查：Linux 上直接启动内置程序，传入 `app-server`；退出处理清理进程，没有在退出回调中重新启动。ARM64 与同版本 x64 包内的扩展 JavaScript 完全一致。预发布版与 26.1021.22027 的扩展 JavaScript 和 x64 Codex 程序逐字节一致。

测试使用 [官方 app-server 协议](https://learn.chatgpt.com/docs/app-server) 的初始化、列表和恢复接口。结果汇总见 [兼容矩阵](scripts/validation/compatibility-matrix.json)，原包和程序 SHA-256 见 [包校验值](scripts/validation/compatibility-packages.json)。每个结果对应的完整日志和退出状态随包提供。

## 测试环境修正

预发布版恢复聊天时需要 bubblewrap。最初仅提取 Codex 可执行文件，恢复测试因缺少该组件失败；补入官方包内的 bubblewrap 后，最小 initramfs 根文件系统又无法执行 `pivot_root`。测试环境改为在内存中建立 tmpfs 根文件系统后，x64 和 ARM64 均通过。没有关闭 Codex 沙箱，也没有修改真实服务器。

## 尚未覆盖

三个新增版本尚未逐一在真实 Remote-SSH 窗口中登录、生成回复及验证窗口重载。真实长聊天、分页与归档、跨服务商加密历史、SSH 断连恢复仍需在目标环境验收。隔离测试通过说明已测试的迁移、索引和恢复接口兼容，不保证所有服务商和历史内容都能继续生成回复。

如果官方 Codex 自动更新到支持列表以外的版本，Easy Switch 会停止切换。请使用已列出的版本，或先对新版本完成兼容测试。
